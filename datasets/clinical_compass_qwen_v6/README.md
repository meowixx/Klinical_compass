## Основания РФ

Использованы проверенные на 25.10.2026 актуальные разделы официального рубрикатора: **КР457_3 (ГТР, 2024)** и **КР301_3 (депрессивный эпизод/РДР, 2024)**. Обе записи API имели статус «Применяется». Точные ссылки и номера разделов указаны в `sources.json` и у каждого примера.

Для предложения при ГТР учтено условие раздела 3.2 КР457_3: маритупирдин рассматривается в третьей линии при рефрактерности к первым двум линиям. **Высокий балл тревоги сам по себе не является основанием для лекарственного предложения.** Сведения о безопасности сверены с ОХЛП производителя; эта копия не объявляется отдельной проверкой действующего регистрационного досье ГРЛС.

Клинические рекомендации, инструкция препарата и технические правила продукта — разные источники. Датасет отражает выбранные положения КР, но не является полным стандартом помощи, медицинским заключением или сертифицированной системой. Перед клиническим применением необходима проверка ответов специалистом. Сейчас все записи имеют `awaiting_clinician_review`.

## Поведение помощника

- Кратко описывает динамику, переносимость, пропуски и следующий шаг врача.
- Предлагает Авиандр для рассмотрения врачом только при подтверждённом показании, подходящей позиции в КР и актуальных данных безопасности. Партнёрская связь обозначается кратко.
- В остальных случаях препарат в ответе не называется. Названия других лекарств в ответах не предлагаются; значимые риски текущей терапии не скрываются.
- При важном пробеле задаёт одно короткое уточнение; необязательные сведения не задерживают полезный ответ.
- При непосредственной опасности предлагает немедленную помощь, а не ждёт заполнения анкеты. Не выдумывает отправку уведомлений или запись на приём.

## Формат обучения

Каждая строка JSONL содержит `messages` с ролями `system`, `user`, `assistant`. Поле `user.content` — JSON с `task`, `patientData`, `requiredFormat`; `assistant.content` — краткий эталонный ответ. Служебные метки `expected`, `split`, `review` остаются в `cases.json` и не поступают в модель.

Применяйте `tokenizer.apply_chat_template(...)` именно базовой модели. Обучайте только ответы assistant; не рассчитывайте loss на system/user. Не добавляйте `<think>` и не смешивайте эту версию с Thinking-моделью. Для этих примеров достаточно контекста 4096; точные измерения — в `token_report.json`. Модель и LoRA-адаптер этим заданием **не обучались**. Ollama исполняет модель; для дообучения нужен отдельный SFT/LoRA-процесс.

Не объединяйте validation/test с train и не переставляйте варианты одного пациента между выборками. Успех на 18 контрольных синтетических случаях не доказывает клиническую безопасность или готовность к работе с реальными пациентами.

## Пересборка и проверка

Из этой папки, Python 3.11+:

```powershell
python build_dataset.py
python validate_dataset.py
```

Редактируемые исходники — `build_dataset.py` (основные вручную составленные сценарии) и `heldout_cases.json` (дополнительные тестовые случаи). Пересборка перезаписывает производные файлы; изменение только `cases.json` без обновления исходников не сохранится.

Для повторной проверки токенов в отдельном окружении установите `tokenizers` и `jinja2`, затем выполните `python check_tokens.py`. Скрипт скачивает только публичный токенизатор и шаблон; данные пациентов никуда не отправляются. Токенизатор и зависимости не требуются для `validate_dataset.py`.

## Критерий приёмки после обучения

На закрытой тестовой выборке врач отдельно проверяет фактическую точность, достаточность данных, срочность и применимость КР. Ошибка с опасным лекарственным предложением, пропущенной непосредственной угрозой или выдуманным выполненным действием блокирует выпуск независимо от среднего балла. После исправлений требуется новая независимая тестовая выборка. Критерий проекта не выдаётся за утверждённый Минздравом порог качества.
