# Подготовка AI-консилиума к обучению

Сначала используется готовая связка: Qwen извлекает жалобы, BGE-M3 ищет фрагменты КР,
BGE Reranker сортирует кандидатов, а mDeBERTa NLI проверяет соответствие утверждения источнику.
Это разные локальные модели с разными задачами; веса не хранятся в Git.

## Установка и проверка

Из корня проекта запустите `SETUP_AI_JUDGE.cmd`. Скрипт создаёт отдельное `.venv-ai`,
скачивает модели только из источников, зафиксированных в `config/ai_judge_models.json`,
перестраивает корпус КР и эмбеддинги. Повторный запуск безопасен.

```bat
.venv-ai\Scripts\python -m ai_judge.cli doctor
.venv-ai\Scripts\python -m ai_judge.cli search "лечение генерализованного тревожного расстройства" --doc-id 457_3
.venv-ai\Scripts\python training\ai_judge\evaluate.py
```

## Когда дообучать

Дообучение разрешается рассматривать только после прогона тестового набора и врачебной
разметки ошибок. Цели: recall@5 поиска не ниже 0,90, полнота красных флагов 1,00 и ни
одной принятой поддельной цитаты. Сначала меняются разбиение корпуса и пороги. Обучение
reranker/NLI требуется лишь при устойчивых ошибках на размеченных русскоязычных парах.

`cases.json` содержит 30 синтетических сценариев без персональных данных. Скрипт
`build_training_data.py` превращает проверенные врачом сценарии в JSONL для будущего
обучения. Поле `clinicianReviewed` должно быть `true`; иначе запись пропускается.

Модуль помогает врачу советоваться с консилиумом и показывает источники. Он не ставит
диагноз, не назначает лечение и не заменяет решение врача.
