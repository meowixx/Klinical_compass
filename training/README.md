# Локальное дообучение Qwen

В корне проекта дважды нажмите **TRAIN_MODEL.cmd**. Нужен Python 3.11/3.12 x64, NVIDIA RTX 30/40/50, свежий драйвер, интернет для первой установки и не менее 25 ГБ свободного места. Скрипт использует отдельное `.venv-training`; окружение FastAPI не меняется.

Первый запуск установит CUDA PyTorch и библиотеки, скачает исходные веса Qwen3-4B-Instruct-2507 и обучит LoRA-адаптер. Модель Ollama в GGUF не используется как обучаемый исходник. Код и revision базовой модели закреплены; `trust_remote_code=False`. WSL и отдельная установка CUDA Toolkit не нужны для выбранных готовых пакетов.

## Перед запуском

Закройте игры и приложения, занимающие видеопамять. Если модель загружена в Ollama, освободите её командой `ollama stop qwen3:4b-instruct`. Для ноутбука подключите питание и отключите автоматический сон на время работы. Скрипт сам не завершает чужие процессы и не отправляет данные на внешние сервисы. Сеть нужна для скачивания зависимостей и исходной модели.

Проверка без загрузки полных весов и без обучения:

```bat
TRAIN_MODEL.cmd -CheckOnly
```

Этот режим всё равно устанавливает библиотеки при первом запуске, скачивает маленькие файлы токенизатора и проверяет CUDA/NF4. Сообщение `CHECK PASSED` не подтверждает, что полное обучение поместится в VRAM.

## Параметры

`training/config.json`: NF4 с двойным квантованием, BF16, LoRA rank 8 для q/v-проекций, batch 1, накопление градиента 8, 2 эпохи, learning rate 0.00005, ограничение 1536 токенов. Loss считается только на ответе assistant; system/user замаскированы. Длинные записи не обрезаются молча. Для экономии памяти словарные logits строятся только для ответной части, с корректным сдвигом causal loss. Замороженные словарные матрицы хранятся в BF16.

Это экономный стартовый профиль для RTX 3060 Laptop 6 ГБ. Реальная вместимость зависит от свободной видеопамяти и системных расходов; заранее гарантировать её нельзя. При нехватке памяти скрипт выдаст понятную ошибку. Не уменьшайте длину ниже длины примеров; используйте освобождённую GPU или второй ПК с большей VRAM. ОЗУ и видеопамять — разные ресурсы.

## Результаты

Каждый запуск создаёт новую папку `training/runs/<дата-время-pid>/`:

- `adapter/` — адаптер лучшего checkpoint по validation loss и токенизатор;
- `baseline_adapter/` — начальное состояние адаптера до обновления весов;
- `checkpoints/` — сохранённые этапы по эпохам;
- `result.json` — результаты до и после обучения, выбранный checkpoint;
- `status.json`, `environment.json`, `run_config.json` — статус, версии и настройки;
- `error.log` — подробности, если возникла ошибка.

Журнал запуска — `training/logs/`. Веса, кеш и окружение исключены из Git. Исходный сайт и модель Ollama не заменяются автоматически. При прерывании готовые checkpoint сохраняются; повторный двойной щелчок начинает отдельный новый эксперимент, а не продолжает предыдущий.

## Проверка качества

Обучаются 52 записи, 12 используются для выбора checkpoint. 18 тестовых записей в тренировочный код не загружаются. Уменьшение validation loss не доказывает клиническую безопасность. Если loss ухудшился относительно исходного состояния, программа сообщает об этом. Адаптер не следует подключать к сервису до независимой проверки тестовых ответов и врачебной оценки: датасет пока имеет статус `awaiting_clinician_review`.

Обучение и экспорт в Ollama — отдельные этапы. `.safetensors` адаптер нельзя просто переименовать в GGUF. После проверки результата нужен совместимый экспорт/объединение с той же базовой моделью и настройка сервиса.

## Проверка ответов и подключение к сайту

`CHECK_MODEL.cmd` сравнивает исходную модель и адаптер на 18 отложенных случаях. Принимает `-Run "путь к запуску"`, по умолчанию берёт последнее завершённое обучение. Перед проверкой остановите локальный сервер адаптера через `start-project.cmd stop`, чтобы не загружать две модели в 6 ГБ VRAM. Проверка не запускает обучение и не меняет веса. Результаты — `evaluation-<время>/answers.jsonl` внутри выбранного запуска: вход, эталон, оба ответа, время и признак обрезки. Эталон не передаётся модели. Повторные проверки этого же набора уже не являются новым независимым испытанием.

Для работы сайта добавлен `training/serve_adapter.py`: он загружает исходную Qwen закреплённой версии и адаптер напрямую, без преобразования в GGUF. Использует уже установленное `.venv-training` и локальный кеш. Сервис слушает только `127.0.0.1:11435`, требует локальный токен, обрабатывает одну генерацию за раз и не записывает тексты пациентов в журналы. FastAPI по-прежнему проверяет права пользователя. Переполнение контекста, незавершённый ответ или занятая GPU приводят к явному резервному ответу, а не к скрытой подмене моделью другой версии.

Выбор проверенного запуска хранится в `config/ai_runtime.local.json` (не публикуется в Git): `enabled`, `model`, относительный `run`, `adapterSha256`, относительный путь `review`. В файле ревью должны совпадать SHA256 адаптера и `engineeringDeploymentApproved: true`. Это техническое разрешение на выдачу черновиков врачу, а не клиническая сертификация. Сервер проверяет хеш перед загрузкой. `start-project.cmd` автоматически запускает выбранный адаптер, его пункт остановки завершает также этот процесс. Если локального профиля нет, используется прежняя конфигурация Ollama. Для отката задайте `enabled: false`, остановите проект и запустите снова.

На другом ПК необходимо восстановить отдельное окружение через `TRAIN_MODEL.cmd -CheckOnly`, перенести папку выбранного запуска (как минимум `adapter`, `run_config.json`, `result.json`, файл ревью) и кеш исходной модели либо скачать исходную модель той же ревизии. Скопированное с другого ПК виртуальное окружение использовать нельзя. Наличие адаптера и кода в рабочей папке не означает, что веса автоматически отправлены на GitHub.

Если проверка обнаружила критические ошибки, профиль получает `blocked: true`: сайт явно сообщает об этом и возвращает структурированные факты вместо генерации. Автоматического переключения на исходную модель в этом состоянии нет. Удаление блокировки без устранения ошибок и нового ревью не является проверкой качества.
